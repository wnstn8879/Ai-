# IMAGINE 온라인 창작실

주소: https://imagine-story-world.angksehdfur2468.chatgpt.site

휴대폰 Chrome에서 주소를 열고 이 사이트를 만든 ChatGPT 계정으로 로그인합니다. APK, PC, USB 설치 과정은 없습니다. 현재는 소유자만 접근하는 비공개 창작실이며, 타인에게 링크만 전달해 공개할 수 있는 서비스는 아닙니다.

## 직접 확인할 흐름

1. 장르를 고르는 대신 섞고 싶은 세계·인물과 원하는 감정을 적습니다. 예시도 자유롭게 수정할 수 있습니다.
2. 상상 원문을 먼저 서버에 저장한 뒤 실제 Qwen 모델로 첫 소설 장면을 생성합니다. 모델 실패 시 원문은 남습니다.
3. 보관함에서 작품을 다시 열고 원하는 방향으로 이어 씁니다. 생성된 장면은 자동 저장합니다.
4. 소설의 구절을 선택한 뒤 ‘이 장면을 다른 방향으로’를 누릅니다. 선택하지 않으면 장면 전체를 대상으로 합니다. 확인 창의 구절과 새 방향을 확인한 뒤 분기를 만듭니다.
5. 분기는 해당 구절 **직전까지**의 본문을 복사합니다. 선택한 구절과 이후 전개를 새 방향으로 쓰며, 원본의 본문·이후 장면은 그대로 유지합니다. 부모 작품으로 돌아가는 버튼을 제공합니다.
6. ‘세계·인물 기억’에 인물의 바람·관계·감정·약속과 중요한 사건을 기록합니다. 다음 생성의 문맥에 반영하며, 저장 지점과 분기는 해당 시점의 상태를 복원합니다. 자동 사건 추출이나 무제한 장기 기억은 아닙니다.
7. ‘읽는 위치 저장’으로 현재 끝 장면에 체크포인트를 만들고, 그 위치에서 다른 이야기를 시작할 수 있습니다.

소설/역할극 형식, 기존 회원 인증·권한·LLM 공급자 어댑터·체크포인트·분기 모델을 재사용합니다. `web/`은 같은 저장소와 API를 사용하는 브라우저 클라이언트입니다. 새로운 각본형 게임을 별도로 만든 것이 아닙니다. Expo 앱과 기존 기록은 유지합니다.

## 배포 구조와 현재 한계

Sites의 Worker가 브라우저 화면과 비공개 API 입구를 제공합니다. D1에는 사용자별 요청 큐와 읽기 캐시를 저장합니다. 익명 방문은 로그인으로 안내하고, 플랫폼이 제공한 사용자 ID만 신뢰합니다. 브라우저가 보낸 서비스 키나 사용자 대리 헤더로 로그인할 수 없습니다.

실제 API와 Qwen/Ollama는 현재 개발 환경에서 실행합니다. 외부에서 백엔드 포트를 열지 않고 인증된 outbound relay가 작업을 받아 기존 FastAPI로 전달합니다. 비공개 게이트웨이 모드에서는 서비스 키가 없는 일반 HTTP 접근을 차단합니다. AI 요청 ID와 서버 영수증으로 같은 생성 요청의 중복 저장을 방지합니다. 비용을 발생시킬 수 있는 생성은 자동 재시도하지 않습니다.

**이 연결은 임시 체험용입니다.** 개발 환경이나 relay가 멈추면 새 생성·수정은 중단됩니다. 마지막으로 동기화된 작품과 체크포인트는 계정별 D1 캐시에서 읽을 수 있지만, 이는 복구용 주 데이터베이스나 운영 백업을 대신하지 않습니다. 원본 데이터베이스는 `.runtime/imagine-online.sqlite`에 있으므로 환경 삭제 전 별도 백업이 필요합니다. 캐시된 기록은 마지막 동기화 시점 기준입니다. 상시 AI 서비스·GPU 서버·운영 백업을 배치한 상태가 아닙니다.

CPU 체험 서버에서는 첫 생성에 수 분이 걸리거나 시간 제한으로 실패할 수 있습니다. 장편 품질과 감정이입은 사용성 검증이 필요합니다. 짧게 끝내도록 줄거리를 강제하는 대신 한 번에 짧은 장면을 이어 씁니다. 공개 게시·독자 간 2차 창작 허용·수익 배분·소설의 게임 변환·브라우저 공동 플레이는 후속 기능입니다. 기존 모바일 친구/멀티플레이 API가 있다고 해서 이 웹 화면에서 모두 연결됐다는 뜻은 아닙니다.

## 개발과 다시 연결하기

```sh
cd web
npm ci
npm test
npm run build
```

`db/schema.js`와 `drizzle.config.js`를 기준으로 스키마 변경 시 `npm run db:generate`로 **새 마이그레이션**을 추가합니다. 이미 적용한 `drizzle/0000_*.sql`을 수정하지 않습니다. `.openai/hosting.json`의 기존 `project_id`와 `d1: "DB"`를 유지합니다.

이 환경에는 Sites 표준 source helper 파일이 없어 `web/scripts/sync-source.py`로 동일한 Git 동기화를 수행했습니다. 배포용 별도 checkout에 `web/` 소스를 동기화하고, 짧게 유효한 저장소 credential을 숨김 표준입력으로 전달합니다. 토큰은 환경의 Git HTTP header로만 사용하며 remote URL·파일·커밋에 남기지 않습니다. 소스를 push한 SHA에서 빌드하고 `.openai/hosting.json`, `dist/server`, `drizzle`를 아카이브해 같은 Site에 저장·배포합니다. 앱 저장소의 `main`에는 병합하지 않습니다.

기존 Qwen 모델을 Ollama로 실행한 뒤 다음 private runner를 사용합니다. 이 스크립트는 프로젝트 ID와 DB 경로를 인수로 받고 서비스 키를 터미널에 표시하지 않고 읽습니다.

```sh
cd backend
PYTHONPATH=. ../.venv/bin/python scripts/serve_online_preview.py \
  --site-id appgprj_6afdaf1a6c8081918371dbd8b9592e12 \
  --database /workspace/StoryVerse/.runtime/imagine-online.sqlite --port 8111
../.venv/bin/python scripts/sites_relay.py
```

runner 기본값은 `qwen3:4b-instruct`, 2 CPU threads, 500 output tokens, 최대 180초입니다. 일반 모바일 서버의 기본 40초 제한은 유지합니다. relay의 숨김 JSON 입력은 `site`, `bypass`, `key` 필드로 구성합니다. `bypass`는 플랫폼이 제공한 서비스 접근 credential이며, `key`는 Sites 환경의 `RELAY_KEY`와 백엔드 서비스 키에 동일하게 설정하는 32자 이상의 무작위 비밀값입니다. 실제 값은 문서·환경 예시·로그·Git에 기록하지 않습니다. 이 서비스 credential은 브라우저 사용자 로그인 권한을 부여하지 않습니다.

## 검증 범위

백엔드 테스트는 구절 일치·유니코드 위치·접근 차단·원본 보존과 서비스 인증을 검사합니다. Worker 테스트는 실제 SQLite에 배포용 마이그레이션을 적용하고 사용자별 캐시 격리·CSRF 차단·작업 단일 수신·오래 걸리는 비동기 생성·중복 요청 재사용을 검사합니다. 실제 모델 검증 결과는 검증 기록에 별도로 남깁니다.

현재 환경에는 지원되는 공유 브라우저 도구가 없어 배포 화면에서의 클릭·휴대폰 텍스트 선택·키보드 표시·실기기 화면은 검증하지 못했습니다. 이 작업은 웹 배포이며 새 Android APK를 빌드한 것이 아닙니다.

2026-11-18 검증: SQLite 백엔드 **68개**, 모바일 **37개**, Worker **7개**가 통과했습니다. 마지막 배포 중 quote formatting으로 페이지 import가 번들에 남는 오류가 발생해 빌드의 import 처리를 수정하고, 실제 배포 번들을 import해 실행하는 회귀 테스트를 추가했습니다. 이 수정 이후 동일 주소로 재배포가 성공했습니다. PostgreSQL은 이번 환경에서 다시 실행하지 않았습니다.

실제 Qwen3 4B 소설 API는 **147.54초**에 성공했습니다. 저장·동일 요청 재전송·구절 분기·원본 보존을 함께 검사한 [실제 검증 기록](validation/online-qwen-novel.json)을 남겼습니다. 이 시간은 로컬 모델/API 경로의 측정이며 브라우저에서 느끼는 전체 시간과 같지 않습니다. 앞선 40초/180초 실행은 실패했고, CPU thread 조정과 프롬프트 길이 조정 후 성공했습니다. 생성문에는 어색한 표현과 세계관 반영 누락이 있어 상용 창작 품질이 완성됐다고 판단하지 않습니다.

최종 Sites 배포 상태는 `succeeded`입니다. 배포 소스 SHA는 `9e0fec536a838be6411514b6f909f977b14b03ff`이며 앱 변경은 `feat/storyverse-auth-library-social`, [PR #1](https://github.com/wnstn8879/Ai-/pull/1)에 반영합니다. 사용자 저장소의 main에는 병합하지 않습니다.
