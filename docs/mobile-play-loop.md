# 휴대폰 중심 플레이 방향

핵심은 출근길에 짧은 장면을 즐기고, 원하면 혼자 오래 이어갈 수 있는 이야기입니다. PC·USB·Metro를 일반 이용자의 사용 조건으로 삼지 않습니다. 기존 Windows 실행 도구는 개발/QA 용도로만 유지합니다.

## 이번 변경

- AI는 약 5번의 응답을 하나의 작은 장면으로 삼아 진행하도록 안내합니다. 응답은 짧은 한국어 문장 3~6개, 두 문단 이내를 목표로 합니다. 뒤쪽 응답에서는 새 갈등을 계속 추가하기보다 자연스러운 쉼을 유도합니다.
- 이는 모델에 주는 지침입니다. 실제 5분 플레이나 정확히 5번 안의 결말을 보장하는 타이머/강제 종료가 아닙니다. 사용자의 선택을 대신 결정하거나 전체 이야기를 끝내지 않습니다. 실제 모델의 속도와 몰입도는 플레이 테스트로 조정해야 합니다.
- ‘이번 장면 짧게 마무리’는 명시적인 AI 요청을 전송합니다. 기존 입력 초안을 유지하며, AI 오류/비용/재시도 정책도 기존 발신 큐를 따릅니다. AI 요청만으로 저장 성공을 주장하지 않습니다.
- ‘저장하고 쉬기’는 전송 대기 기록이 없는지 확인하고 최신 서버 기록 위치에 개인 체크포인트를 만든 뒤 보관함으로 돌아갑니다. 저장이 실패하면 방에 남아 오류를 표시합니다. 미전송 초안은 서버 체크포인트가 아니라 기기 저장입니다.
- 각 메시지의 개인 분기는 원본 보존·선택한 위치까지 복사·독립된 혼자 플레이임을 확인한 뒤 생성합니다. 이후 기록과 당시 세계관/캐릭터 상태는 기존 분기·스냅샷 기능을 사용합니다.

## 저장과 재개 원칙

서버에 확정된 메시지는 자동 보존합니다. 마지막 장면은 보관함에서 이어가고, 과거 메시지 또는 저장 지점은 새 개인 분기로 재개합니다. 원본 기록은 잘라내지 않습니다. 멀티플레이에서 개인 분기로 나와 혼자 계속할 수 있고 다른 참가자의 방은 영향을 받지 않습니다. 공용 복원은 기존 방장·전원 동의 절차를 유지합니다.

## 휴대폰 단독 배포에 남은 조건

현재 내려받을 수 있는 debug APK는 Metro에 의존하는 개발 빌드입니다. 이번 UI 변경만으로 휴대폰 단독 실행 버전이 되지는 않습니다. 이용자용 배포에는 상시 HTTPS 백엔드·PostgreSQL·서버 비밀키 설정·독립 실행 APK/AAB 빌드와 서명·실제 Android 기기 검증이 필요합니다. 실제 AI에는 서버의 LLM 키도 필요합니다. 공개 배포는 이번 작업에 포함하지 않습니다.

다음 제품 검증은 짧은 실제 출근길 세션에서 장면 길이·지루함·자연스러운 쉼, 저장 후 재실행, 과거 선택 분기를 확인하는 것입니다. 대화가 길어질 때의 페이지네이션·오프라인 전체 기록 캐시는 별도 후속 과제입니다.

## 이번 변경의 검증

로컬 백엔드 pytest 42개, 모바일 Node 테스트 25개, Android JS/Hermes 번들 생성이 통과했습니다. 새 테스트는 전체 기록 기준의 장면 진행·계속 플레이·사용자 요청 보존과 LLM 어댑터로 전달되는 지침을 검사합니다. DB 스키마 변경은 없습니다. 실제 LLM API의 서사 품질·변경된 화면의 실기기 터치·휴대폰 단독 APK 실행은 미검증입니다. 기존 Windows ZIP은 이번 변경을 포함하지 않는 이전 개발용 산출물입니다.
