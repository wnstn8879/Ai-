# 기기 초안과 영구 전송 큐

## 저장 범위

`expo-sqlite`의 앱 전용 `storyverse-outbox-v1.db`에 메시지 입력 초안과 전송 요청을 저장합니다. 서버 주소·사용자 ID·방 ID로 분리합니다. 다른 계정은 이전 계정의 초안/전송 기록을 읽거나 그 계정의 요청을 보낼 수 없습니다. 로그아웃하면 화면에서 제거하고, 같은 계정으로 다시 로그인하면 해당 기록을 복원합니다. 서버 주소를 바꾸면 기존 서버 기록을 새 서버로 자동 이전하지 않습니다.

비밀번호·접근/갱신 토큰은 이 DB에 넣지 않습니다. 인증은 기존 SecureStore를 유지합니다. 이야기 초안/요청 본문은 앱 전용 SQLite에 저장하며 별도의 SQLCipher 암호화는 적용하지 않았습니다. Android 자동 백업은 비활성화해 기기 전송 기록을 백업으로 복사하지 않습니다. 앱 삭제 시 아직 서버에 도착하지 않은 기기 기록도 삭제됩니다.

메시지 입력은 변경마다 직렬로 저장하며 `초안 저장 중…`, `초안 저장됨`, 실패 상태를 표시합니다. 저장 완료 표시 전에 강제 종료하면 마지막 입력이 남지 않을 수 있습니다. 메시지 입력 초안을 보존하는 기능이며 세계관/캐릭터 편집 폼의 미저장 초안까지 보존하지는 않습니다. 과거 대화 전체의 오프라인 캐시는 아니므로 스토리를 열려면 서버 연결이 필요합니다.

## 전송과 재시도

전송 버튼은 네트워크 요청보다 먼저 요청 ID·방·종류·작성자·본문을 SQLite 트랜잭션으로 저장합니다. 큐 저장에 실패하면 HTTP 요청을 보내거나 초안을 지우지 않습니다. 큐 추가와 같은 트랜잭션에서 일치하는 초안만 지워 새로 작성한 내용을 덮어쓰지 않습니다.

일반 메시지는 앱이 전면에 있는 동안 연결 복구/재시작 후 자동 재전송합니다. 앱을 완전히 종료한 동안 서버로 보내는 OS 백그라운드 서비스는 아닙니다. 재전송에도 기존 요청 ID와 본문을 그대로 사용하며 서버의 영구 영수증으로 이미 도착한 메시지를 확인합니다. 앱 종료·응답 유실·서버 재시작 후에도 중복 저장을 막습니다. 서버에 도착한 메시지의 전체 순서는 서버가 부여하며 기기 큐는 같은 방 안에서 자신의 대기 요청 순서를 보존합니다.

- 네트워크/시간 초과/서버 5xx: 최대 60초까지 증가하는 대기 후 재시도.
- 429: 숫자로 된 `Retry-After`를 따릅니다(없으면 60초).
- 409: 자동 재전송을 멈추고 사용자의 확인을 기다립니다.
- 접근 불가/잘못된 입력 등의 4xx: 차단 상태로 남겨 사용자가 확인합니다.
- 같은 방의 앞선 요청이 대기/확인/차단 상태이면 뒤의 요청을 먼저 보내지 않습니다. 다른 방의 큐는 별도로 진행합니다.
- 전송 중인 기기 기록은 삭제하지 못합니다. 대기 기록을 삭제해도 이미 서버에 도착한 메시지는 삭제하지 않으며 이를 삭제 확인창에 안내합니다.

같은 계정의 미완료 요청은 최대 100개입니다. 완료된 기록은 시작 시 7일이 지난 항목을 정리하며 미완료 기록을 임의로 버리지 않습니다. 기록은 채팅 화면과 홈/보관함에서 확인·재시도·정리할 수 있습니다.

## AI 요청

AI 요청도 먼저 기기에 저장하되 사용자가 누른 최초 전송/명시적 다시 보내기에만 실행합니다. 앱 재시작, 네트워크 실패, 서버 오류 또는 충돌 후에는 확인 상태로 남겨 자동으로 AI 비용이나 이야기 진행을 발생시키지 않습니다. 한 방에는 미완료 AI 요청을 하나만 둡니다.

이미 완료된 AI 턴은 같은 요청 ID로 저장된 결과를 반환합니다. 아직 서버에서 처리 중인 AI 호출을 한 번만 실행하는 분산 작업 큐는 별도 후속 작업입니다. 기기 큐가 외부 모델 호출의 정확히 한 번 실행이나 실제 응답 품질까지 보장하는 것은 아닙니다.

## 계정 전환

워커는 현재 사용자와 일치하는 요청만 `requestForUser`로 보냅니다. 계정이 바뀌거나 로그아웃하면 새 요청을 멈추며, 이전 계정의 늦은 응답은 화면에 반영하지 않습니다. 이미 서버로 보낸 요청은 서버에서 처리될 수 있으므로 이전 계정의 기록은 보존하고 재로그인 시 같은 ID로 확인합니다. 토큰을 큐에 저장하거나 다른 계정의 토큰을 대신 사용하지 않습니다.

## 검증

Node 테스트는 테스트 대역 SQL이 아니라 실제 SQLite 파일을 닫고 다시 여는 방식으로 초안·큐 복원, 트랜잭션 실패, 계정/서버/방 분리, 응답 유실, 동시 워커, FIFO, 429, AI 명시적 확인, 저장 한도를 검증합니다. 서버 pytest는 실제 API의 동시 동일 ID 요청과 별도 서버 프로세스 재시작 이후 영수증 재사용을 확인합니다.

Android QA에는 초안 저장 후 프로세스 재시작, 서버를 일시 정지한 상태의 전송 후 앱 강제 종료·복구, 두 에뮬레이터의 네이티브 대화/동의를 추가했습니다. 실제 실행 결과는 `implementation-status.md`와 CI에서 확인합니다. 두 에뮬레이터 검증은 두 실제 스마트폰 검증과 구분합니다.
