# 읽는 동안 이어 쓰는 소설

## 사용자가 원하는 경험

처음에 상황·세계·인물·원하는 감정을 정하면, 이후 사건과 행동·대사·감정은 AI가 스스로 이어 씁니다. 독자가 매 장면마다 선택하거나 ‘다음’을 입력하는 방식에서 벗어납니다. 원하는 순간에 방향을 한 번 바꾸고, 큰 갈림길에서는 AI에게 맡기거나 새로운 분기로 갈 수 있습니다.

기존 소설 프롬프트의 ‘최대 300자/짧은 두 문단’ 지침을 제거했습니다. 자동 집필은 5~8문단, 약 600~1,000자를 목표로 여러 부분을 이어 쓰도록 요청합니다. 이는 모델에 주는 목표이며 매번 정확한 글자 수를 보장하지 않습니다. 역할극 모드의 짧은 출근길 장면 규칙은 별도로 유지합니다.

## 온라인 동작

[기존 IMAGINE 창작실](https://imagine-story-world.angksehdfur2468.chatgpt.site)에서 ‘이 상상으로 자동 집필 시작’을 누릅니다. 기존 작품은 ‘자동으로 이어 읽기’를 누릅니다. 매번 지시하지 않아도 사건을 이어 쓰며, 완성된 부분과 작성 중인 초안을 구분해 표시합니다.

- **잠시 멈추기:** 스트림 연결을 취소하고 지금까지 표시한 초안을 보존합니다. 다시 시작하면 저장된 초안 뒤를 이어 쓰도록 모델에 전달합니다. 기존 본문을 덮어쓰지 않습니다.
- **원할 때 한 번만 개입하기:** 쓰는 중 넣은 방향은 다음 부분에 한 번 반영합니다. 이미 쓰고 있던 부분을 되돌리거나 즉시 다시 쓰는 기능은 아닙니다. 이후 장면의 설정과 결과는 저장된 이야기 문맥으로 남습니다.
- **큰 갈림길:** 모델이 돌이킬 수 없는 선택 앞에서 별도 질문을 남겼을 때 자동 진행을 멈춥니다. 질문은 본문과 분리합니다. ‘자동으로 이어 읽기’로 맡기거나, 방향을 적거나, 그 지점까지의 원문을 보존한 개인 분기를 만들 수 있습니다.
- **읽는 동안 계속 집필:** 브라우저는 연속 읽기를 명시적으로 시작합니다. 네 부분 같은 고정 분량에서 강제로 멈추지 않고, 화면을 열어둔 동안 다음 부분을 이어 씁니다. 큰 갈림길, 사용자 정지, 연결 만료, 오류, 기존 일일 요청 한도에서 멈춥니다. API의 `continuous=false`는 검증/제한 집필을 위해 1~6부분을 처리하는 별도 방식이며 온라인 읽기는 `continuous=true`입니다.

갈림길은 모델이 판단하는 서사 장치입니다. 중요한 선택을 항상 정확하게 탐지하는 규칙 엔진이나 자동 모순 검사가 아닙니다. 앞서 저장한 원문/설정에 근거해 집필하도록 기억 검색·입력 예산을 재사용합니다.

## 스트리밍과 저장

기존 단일 `/turns` 요청의 완료를 기다리는 대신, 짧은 start/status/control 요청을 사용합니다. 실제 모델의 스트리밍 텍스트는 백엔드의 `novel_writers.draft`에 조각마다 저장하고, 화면은 해당 상태를 조회해 새 본문을 표시합니다. 전체 모델 호출이 Sites relay의 한 HTTP 요청을 몇 분씩 점유하지 않습니다. 공급자 API 키와 서비스 키는 서버에만 있습니다.

완료 신호가 오면 초안에서 본문/갈림길 질문을 분리하고 기존 Message와 기억 인덱스에 원자적으로 반영합니다. 생성 중 메시지/상태가 바뀌면 오래된 결과를 본문에 반영하지 않고 초안을 보존한 채 멈춥니다. 모델 오류·타임아웃도 초안을 완성된 본문처럼 저장하지 않습니다. 공급자의 출력 길이 제한에 닿으면 저장한 초안으로 최대 세 번 이어 쓰고, 더 길면 쉬어 갑니다. 각 호출은 기존 일일 시도 한도에 포함되며 오류 호출은 자동 재시도하지 않습니다.

중단 후 모델이 새로 시작할 때 앞부분을 중복하거나 사건을 바꾸는지에 대한 일반적인 의미 검증은 남아 있습니다. 저장된 접두부 자체는 보존합니다. 작성 중인 초안은 확정된 캐릭터 사실로 자동 등록하지 않습니다.

`008_novel_writer`는 방별 집필 상태·초안·대기 방향·현재 방향·질문·진행 수·작업 ID·읽기 연결 만료 시간을 가진 테이블 하나를 추가합니다. 기존 원문/상태/체크포인트를 수정하지 않으며 실제 체험 DB는 마이그레이션 전에 백업했습니다. 먼저 `alembic upgrade head`를 실행합니다.

## 실행과 제한

현재 자동 집필은 온라인 브라우저의 개인 소설/소유자에게 연결했습니다. 기존 Expo 역할극/발신 큐는 유지하며, Expo 소설 화면까지 같은 자동 집필 UI로 바꾼 것은 아닙니다. 새로운 APK를 만들지 않습니다.

`AI_WRITER_OUTPUT_TOKENS`는 자동 집필의 호출별 출력 예산입니다(기본 1200, 허용 256~2400). 기존 `AI_MAX_OUTPUT_TOKENS`와 일반 `/turns`의 응답 계약은 유지합니다. 모델 문맥에서 별도로 출력 예산을 남깁니다. 자동 집필 스트림은 유휴 90초/호출 전체 600초 제한이 있으며, thinking 채널과 분할된 thinking 태그는 독서 본문으로 전달하지 않습니다.

앱 화면을 벗어나거나 숨기면 일시정지를 요청합니다. 요청이 전달되지 않아도 읽기 연결은 약 90초 후 만료되어 다음 생성과 현재 스트림을 멈춥니다. 화면을 다시 열었다고 모델을 자동 재시작하지 않습니다. 서버 재시작으로 오래된 실행 상태가 남으면 초안을 보존하고 명시적인 재개를 기다립니다. start/direction 명령은 요청 ID 영수증으로 중복 실행을 방지합니다. 오래된 정지 요청은 새 작업 ID를 정지시키지 않습니다.

백엔드 실행기는 현재 개발 환경의 프로세스 안에서 동작합니다. 상시 분산 작업 큐/운영 추론 서버는 아닙니다. 모델/개발 환경이 멈추면 새 집필은 중단되며 저장된 초안을 읽고 서버 복구 후 다시 시작해야 합니다. CPU 모델의 속도와 문장 품질은 별도 개선이 필요합니다. 실제 휴대폰 브라우저에서 스크롤·선택·화면 전환은 이 환경에서 아직 검증하지 못했습니다.

연속 모드도 기존 사용자/방별 일일 모델 호출 한도를 그대로 적용합니다. 앱을 닫은 뒤 계속 생성하는 백그라운드 서비스가 아닙니다.


## 실제 실행과 자동 검증

실제 Qwen3 4B에서는 첫 본문이 36.51초에 표시됐고, 62.94초에 초안을 일시정지했습니다. 새 상태 조회에서 같은 초안을 읽고, 재개 후 약 174.52초에 총 690자의 한 부분을 저장했습니다. 저장된 접두부가 그대로 유지됐습니다. [실제 결과](validation/auto-writer-real.json)는 원문과 평가를 함께 보존합니다. 이어 붙이는 경계의 음절 중복과 어색한 문장도 확인돼 소설 품질 완료로 표시하지 않습니다.

이 실제 실행은 제한 집필 API로 한 부분의 완료를 확인한 사례입니다. 자동 세 부분 연속 집필, 한 번의 방향 변경, 길이 상한 없이 갈림길까지 계속하기, 질문에서 정지, 일일 한도 정지와 오류/충돌/읽기 연결 만료는 모델 대역을 사용한 통합 테스트로 확인합니다. 대역 테스트를 실제 모델의 서사 판단 검증으로 보지 않습니다.


최종 로컬 검증: 백엔드 pytest 87개와 웹/독서 제어기 12개, 웹 배포 번들이 통과했습니다. 기존 모바일 코드는 이번 작업에서 변경하지 않았으며 새 APK/실기기/브라우저 수동 조작과 PostgreSQL 재실행을 완료했다고 표시하지 않습니다. 기존 비공개 사이트의 소유자 접근 범위를 유지합니다.


최종 Sites 배포는 기존 주소에서 succeeded이며 배포 소스 SHA는 `2ac0086449a9e9ea1056185c08e287bc9dac2a16`입니다. 앱 변경은 기존 `feat/storyverse-auth-library-social`과 [PR #1](https://github.com/wnstn8879/Ai-/pull/1)에 반영하고 main에는 병합하지 않습니다.

마지막 독서 제어 검증은 완성된 본문 동기화 이후에 갈림길 제어를 표시하고, 본문 조회 실패가 다음 상태 확인 때 복구되는지도 포함합니다. 자동 상태 조회의 통신 지연은 읽는 위치를 위로 이동시키지 않고 집필 상태 영역에 표시합니다.
